# Атаки и попадания: что такое «настоящий удар»

## 1. Данные атаки — `BGSAttackData` (`ATKD`)

Каждая атака расы — запись в `TESRace::attackDataMap`: имя события + данные. **[A]** (заголовки CommonLib)

| Поле | Смысл |
|---|---|
| `damageMult` | множитель урона атаки |
| `attackChance` | вероятность, с которой AI выбирает эту атаку (в нашей выгрузке: `bashStart … chance=0.50`) |
| `attackSpell` | **спелл, который накладывается этой атакой** — сюда движок и пишет «эффект удара» |
| `flags` | `kBashAttack`, `kPowerAttack`, `kChargeAttack`, `kRotatingAttack`, `kContinuousAttack`, `kIgnoreWeapon` |
| `attackAngle`, `strikeAngle` | углы конуса атаки |
| `staggerOffset` | сдвиг точки стаггера |
| `knockDown` | сила сбивания с ног |
| `recoveryTime` | время восстановления после атаки |
| `staminaMult` | множитель расхода выносливости |

Вывод: **«баш» как механика = запись с флагом `kBashAttack` + попадание + эффекты из `attackSpell`
и стаггер по `fStagger*`.** Чтобы баш «работал», движок должен провести атаку, а не проиграть анимацию.

## 2. Попадание — `HitData`

Флаги `HitData::Flag` **[A]** (заголовки): `kBlocked`, `kBlockWithWeapon`, `kBlockCandidate`, `kCritical`,
`kSneakAttack`, **`kBash`**, **`kTimedBash`**, **`kPowerAttack`**, `kMeleeAttack`, `kOffhand`, `kExplosion`.

Поля, которые нас касаются: `healthDamage`, **`percentBlocked`** (сколько урона заблокировано),
**`stagger`** (величина стаггера), `pushBack`, `attackData`, `weapon`.

Отсюда следует, что «баш попал» = существует `HitData` с `kBash` и посчитанным `percentBlocked`.
Наш заказ через `NotifyAnimationGraph` такого объекта не создаёт — **[A]** (лог 0.6.2: анимация была,
попаданий нет).

## 3. Попадание в блок

- Если атака пришлась в блок, в `HitData` взводится `kBlocked` (и `kBlockWithWeapon`, если блок оружием),
  а `percentBlocked` считается по формулам UESP с `fBlockPowerAttackMult` для силовых. **[B]**
- Блок в движке **не снимается** ни при каком попадании: он уменьшает урон и может вызвать стаггер,
  который прервёт действие. **[B]** ([`block-bash-stagger.md`](block-bash-stagger.md))
- Поэтому «пробить блок» = вызвать стаггер в момент попадания. Именно так это описано в CK Wiki
  для `Power Attack Blocking Mult`: «power attack … and thus, **break a block**». **[B]**

## 4. Тайминг попаданий (hit frames)

- Какая именно фаза анимации наносит урон, задаётся в поведении (behavior) анимации, а не в данных атаки;
  моддеры правят это отдельными модами («Retimed Hit Frames» и подобные). **[C]**
- Практический вывод: между началом анимации и попаданием есть задержка, поэтому привязка эффекта
  к `bashStart`/`bashStop` всё равно требует допуска по времени. В 0.7.0 эффект накладывается
  по окончанию анимации баша (`bashStop`) и только в пределах дистанции баша (140 при `fCombatBashReach = 141`).

## 5. Что из этого следует для дизайна

| Хотим | Нужен настоящий `HitData`? | Как сделать |
|---|---|---|
| баш наносит урон/стаггер | да | только атака движка: либо AI решает сам, либо мы накладываем эффект отдельно |
| «выбить из блока» | нет | наложить стаггер самим (спелл, перк, `KnockAreaEffect`) |
| «силовая пробивает щит» | нет | стаггер в момент силовой анимации + `fStagger*` для настоящего попадания |

## 6. Опровергнуто

| Гипотеза | Итог |
|---|---|
| «Можно заказать атаку анимационным событием и получить попадание» | нет: `HitData` не создаётся, урона и стаггера нет **[A]** |
| «`attackSpell` в данных расы можно подменить, чтобы баш накладывал наш эффект» | подмена записи в памяти движка = правка ванильных форм; рискованно и не проверено **[D]**, не делаем |
