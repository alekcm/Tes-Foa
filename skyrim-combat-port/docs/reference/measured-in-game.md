## 0.6.2 — лог `TGCombatPort-9.log` (71 строка, 16:06:32–16:07:30)

Главный измерительный лог проекта. Что в нём:

| Строка | Факт |
|---|---|
| `TGCombatPort v0-6-2-0` | версия DLL в игре действительно 0.6.2 |
| `stagger spell: …` × 12, `stagger: выбран спелл Warmaster Knockdown (00106254) из 129 кандидатов` | поиск спелла работает, кандидатов 129 |
| `bash ordered: … event=bashStart sent=true` × 5 | заказ баша проходит |
| `bandit anim: bashStop` × 5 (через 0,12–0,34 с) | анимация начинается и обрывается |
| `bandit anim: bashStart` — **0 раз** | движок не рассылает `bashStart` слушателям |
| `stagger applied` — **0 раз** | наш эффект не вызывался ни разу: триггер стоял на `bashStart` |
| `power window opened` — **0 раз** | правило «силовая по блоку щитом» не включалось: игрок блокировал мечом |
| `diag: blocking=true withShield=false hostiles=1` | игрок всё время блокировал без щита, рядом один бандит со щитом и стальной булавой |

Выводы, на которых стоит 0.7.0:

1. Триггер механики не может быть на `bashStart` — событие не приходит. Надёжный сигнал — `bashStop`. **[A]**
2. Заказ баша анимацией **не создаёт попадания** (это idle-анимация), поэтому «бьёт и не попадает» —
   не баг конкретной версии, а свойство механизма. **[A]**
3. Ванильная силовая атака блок не ломает; ломать должен наш эффект. **[A]** (плюс **[B]** по UESP)

## 0.7.2 — лог `TGCombatPort-11.log` (17:28:34–17:29)

| Строка | Факт |
|---|---|
| `rule fired: [bandit-bash-breaks-weapon-block] via=попадание … effects=unblock,stagger` | движок правил работает: правило из файла сработало на настоящем попадании |
| `hit: … flags=09` | флаги попадания: `kHitBlocked` (8) + `kPowerAttack` (1) — **AS-5 подтверждено** |
| `hit: actor=Бандит kind=spell source=Топот великана (00104D43)` | подобранный спелл-стаггер **бьёт игрока сам** — AS-12 подтверждено (`kind=spell`) |
| `hit: … kind=melee source= (000001F4)` | 000001F4 — форма удара без оружия: спелл наносит ещё и «кулачный» удар |
| `hit: … source=Ошеломление (00072674)` | эффект стаггера приходит отдельным попаданием |
| `block kick: … blockStop sent=true` затем `sent=false` | **AS-10 опровергнуто:** вне стаггера событие принимается (блок слетает — подтверждение пользователя), в стаггере граф его игнорирует, и блок можно поднять снова |
| «разрыв земли» под игроком (наблюдение пользователя) | это визуальный эффект спелла «Топот великана» (площадь > 0), а не наша механика |

Вывод: стаггер должен быть собственным состоянием графа (`staggerStart`), а не спеллом.
Блок в этом состоянии не поднимается; спелл остаётся только запасным путём и теперь требует
нулевой площади и ровно одного эффекта.
