# Предкодовая проверка вертикального среза: паук vs волк vs бандит

**Дата:** 2026-11-21  
**Статус:** техническая оценка, не реализация и не внутриигровая проверка.  
**Цель:** до выбора toolchain разложить утверждённые игровые требования из `skyrim_enemy_combat_design_spec.md` на возможные игровые механизмы и тесты; не менять механику без согласования.

## Целевой профиль и границы проверки

Пользователь сообщил, что играет в Skyrim Special Edition со всеми дополнениями; для проекта это трактуется как полный набор официальных DLC — Dawnguard, Hearthfire и Dragonborn. Точный executable runtime, магазин/платформа и перечень плагинов не указаны. В старых design-документах и workbook используется цель Skyrim AE, поэтому Creation Club/AE-контент, наличие которого не подтверждено, следует держать отдельным optional patch, а не обязательной частью core.

В проверенной coding-среде — Linux x86_64. Creation Kit, xEdit, Papyrus Compiler и Wine не найдены в `PATH`; файлы игры и игровые master-файлы в рабочем репозитории отсутствуют. Это ограничение именно sandbox: Git не предоставляет доступ к локальной установке пользователя. Следовательно, сейчас возможны чтение/подготовка исходников и статические проверки доступными средствами, но не запуск Skyrim или CK здесь.

## Механики и возможная реализация

| Малый паук: шипение 0,65 с, затем только фиксированный leap **или** bite; без web-snare и без наведения в полёте | Сначала проверить существующие spider attack events и Race Attack Data. В текущей sandbox нужного редактора/behavior tool нет. | В игре записать серию leap/bite: tell заметен визуально и слышимо; после старта leap не доворачивает за игроком; у игрока есть время и пространство на sidestep/cover; нет web-root и цепочки контроля. Сравнить 1st/3rd person и бой в тесной пещере. |
| Большой паук: видимая паутина после прицеливания 0,8 с; slow 1,5 с; cooldown 8 с; leap только если цель близко/замедлена | Projectile + Spell/Magic Effect для видимого glob и короткого slow; назначить способность только крупным паукам. Условия дальности/замедления и cooldown проверить на NPC AI/скриптовом состоянии; не считать наличие projectile достаточной реализацией всего цикла. | Записи предметов/магии выглядят отдельным прототипируемым слоем; выбор NPC способности, точный cooldown и условный follow-up не доказаны. Slow не должен стать полной неподвижностью. | Проверить glob при LOS/за укрытием, попадание/промах, длительность 1,5 с, повтор не раньше 8 с, отсутствие эффекта у малых пауков; leap допускается лишь при близкой/замедленной цели и не доворачивает в воздухе. |
| Волки: pack flank; один feint, второй делает lunge через 0,7 с; одновременно активен максимум один leap; одиночный волк использует bite→retreat | Разные CombatStyle/AI-профили могут задавать склонность к кружению, отступлению и давлению; ice wolf может получить отдельный краткий frost effect. Для строгого общего правила «один leap активен на pack» нужен общий gate — возможный кандидат: наблюдение за attack animation events и временное состояние pack controller. Это пока гипотеза, не выбранная зависимость. | CK Wiki прямо ограничивает CombatStyle общим подходом к бою: конкретные решения combat AI нельзя задавать одним CombatStyle. Поэтому только изменение CombatStyle не доказывает взаимное исключение leap у двух актёров. Нужен прототип group gate; если он ненадёжен, альтернативу надо отдельно согласовать. | 1 волк и стая из 2–3: засечь одновременные leap, интервалы и повтор; проверить, что один атакует, пока другой фланкирует/делает feint; проверить retreat у одиночного. Пак не должен загонять игрока в цепочку stagger. |
| Бандит со щитом: feint только если игрок держит block → bash → sword punish; cooldown 7 с; промах bash открывает окно ответа | Papyrus имеет механизм регистрации animation events; кандидат — наблюдать начало/конец block игрока и связать это с отдельным состоянием бандита. CombatStyle может влиять на общую склонность к bash, но сам по себе не гарантирует реакцию строго на block. Для выбора/прерывания конкретной атаки понадобится проверка Combat Override/animation-пути; SKSE не добавлять «на всякий случай». | Нужно проверить названия block events и доставку событий в целевой игре/виде от первого и третьего лица, а также надёжный способ вызвать нужное действие NPC. Условие «feint only if blocking» нельзя молча заменить обычным bash. | Игрок держит block: бандит показывает feint и bash, который можно bait/sidestep; при отсутствии block бандит делает обычные 1–2 удара. После промаха есть окно ровно на player combo; повторный bash не раньше 7 с. Проверить щит, оружие в двух руках/не тот тип, stagger и LOS. |

## Принцип выбора реализации

1. Начинать с vanilla plugin records и Papyrus только для тех элементов, которые подтверждаются небольшим тестом; не считать, что CombatStyle управляет точной последовательностью атак.
2. Сначала проверить возможность переиспользовать vanilla animations/attack events и стандартные Spell/Projectile/Magic Effect records. Любой новый behavior graph или native DLL — отдельное техническое решение, не выбранная сейчас зависимость.
3. Если требование нельзя выполнить предложенным способом, зафиксировать точное ограничение, затронутую механику и минимальную альтернативу. До одобрения пользователя игровое поведение не менять.
4. Target runtime не нужен для доступа к ПК, но нужен перед выбором/сборкой runtime-specific SKSE DLL и для воспроизводимого теста.

## Тестовый протокол после появления локальной сборки

- Изолированный профиль с целевой Skyrim SE и установленными дополнениями; сначала без сторонних combat/animation overhauls. Отдельно проверить, что optional CC patch отключается без ошибок, если соответствующий файл отсутствует.
- Одинаковые уровень игрока, экипировка и сложность для коротких blind-тестов: малый паук, большой паук, один волк, стая из двух волков, бандит со щитом.
- Для каждой встречи записать: увиден/услышан ли tell, какая контрмера выбрана, cooldown, длительность slow/stagger, число последовательных контролей, попадания через укрытие и результат save/reload.
- Проверить две жизнеспособные контрстратегии на семью. Если spider, wolf и bandit побеждаются одним и тем же face-tank/light-attack поведением, критерий различимости не пройден — нельзя компенсировать это простым ростом HP/урона.
- Пользователь запускает Skyrim/CK локально, если инструменты не установлены в sandbox, и возвращает только нужные логи/видеофрагмент/наблюдения; сохранение игры в Git не требуется.

## Источники для технических ограничений

- [Creation Kit Wiki: Combat Style](https://ck.uesp.net/wiki/Combat_Style) — описывает общий стиль, но не точное управление отдельными решениями combat AI; упоминает ограниченную роль Combat Override Packages.
- [Creation Kit Wiki: Race](https://ck.uesp.net/wiki/Race) — Behavior Graph и данные Attack Data относятся к race/animation events и параметрам атак.
- [Creation Kit Wiki: List of Papyrus Functions](https://ck.uesp.net/wiki/List_of_Papyrus_Functions) — справочник Papyrus events/functions, включая `OnAnimationEvent`; конкретные event names и их работу на нужном actor/runtime должны проверяться в игре.
