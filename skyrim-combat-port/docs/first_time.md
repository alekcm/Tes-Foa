# Первый раз: от скачивания до первого лога

Инструкция для первого запуска. Делай по шагам, не перескакивай. После каждого шага есть проверка —
если она не сошлась, остановись и напиши мне, что видишь.

Время: 30–50 минут, из них большая часть — ожидание загрузки Creation Kit.

Названия кнопок в Creation Kit могут немного отличаться в твоей версии/языке. Если пункта нет — напиши,
какие пункты видишь, я поправлю.

---

## Шаг 0. Что должно быть установлено

- Skyrim Special Edition и все дополнения (у тебя есть).
- **Creation Kit**: Steam → Библиотека → в фильтре выбери «Инструменты» → Skyrim Special Edition Creation Kit →
  Установить.
- **Python 3.10 или новее**: python.org → Download. При установке обязательно поставь галочку
  **«Add python.exe to PATH»**.
- Место на диске под проект: любая папка, например `D:\Mods\Tes-Foa`. Путь лучше латиницей и не в OneDrive.

Проверка Python: открой PowerShell (Win+R → `powershell` → Enter) и выполни:

```powershell
python --version
```

Должно быть что-то вроде `Python 3.12.4`. Если пишет «не распознано» — Python не в PATH, переустанови с галочкой.

---

## Шаг 1. Скачать проект

1. Открой страницу репозитория на GitHub.
2. Зелёная кнопка **Code** → **Download ZIP**.
3. Распакуй архив, например в `D:\Mods\Tes-Foa`.
4. Внутри будет папка `skyrim-combat-port` — дальше работаем в ней.

**Важно:** это не мод, а проект. Не кидай эту папку в `Data` игры.

Проверка: в папке `skyrim-combat-port` видны `README.md`, `docs`, `src`, `tools`.

Если проект уже скачивался раньше, а я обновил инструменты, скачай ZIP заново и распакуй **поверх** той же папки:
файл `.env` при этом сохранится, потому что его нет в архиве.

---

## Шаг 2. Проверить, что инструменты на месте

В папке `skyrim-combat-port`: Shift + правый клик по пустому месту → **«Открыть окно PowerShell здесь»**
(или `cd D:\Mods\Tes-Foa\skyrim-combat-port`).

Выполни:

```powershell
python tools\check_env.py
```

Скрипт не знает, где установлена игра, пока ты не укажешь путь. Если он пишет «Файла .env нет» и всё `[нет]` —
это не поломка, а missing настройка:

1. Узнай папку игры: Steam → правый клик по Skyrim Special Edition → **Управление** → **Просмотреть локальные
   файлы**. Откроется папка, где лежит `SkyrimSE.exe`. Скопируй путь из адресной строки проводника.
2. В папке проекта выполни:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. В открывшемся блокноте найди строку `SKYRIM_DIR=` и впиши путь после знака равенства, без кавычек. Пример:

   ```ini
   SKYRIM_DIR=C:\Program Files (x86)\Steam\steamapps\common\Skyrim Special Edition
   ```

   Сохрани и закрой блокнот.
4. Снова запусти `python tools\check_env.py`.

Скрипт также пытается сам найти игру в библиотеках Steam и подсказывает путь, если нашёл.

Ожидаемо: строки `[ok]` у `SkyrimSE.exe`, `Data/Skyrim.esm`, `Dawnguard / Hearthfire / Dragonborn` (3/3),
`Creation Kit`, `PapyrusCompiler.exe`, `TESV_Papyrus_Flags.flg`, `Исходные скрипты игры`.

Если после заполнения `.env` где-то `[нет]` — стоп. Скопируй эти строки и пришли мне. Не начинай CK,
пока не разберёмся. Отсутствие `Creation Kit` и `PapyrusCompiler.exe` означает, что CK ещё не установлен —
это следующий шаг, но сначала пришли вывод.

## Шаг 3. Скомпилировать скрипты

```powershell
python tools\build.py --name TGCombatPort --version 0.1.0 --skip-package
```

Ожидаемо: `Скомпилировано скриптов: 4` и список `Scripts/TGCP_*.pex`.

Что произошло: текстовые `.psc` превратились в `.pex`, которые понимает игра.

Если ошибка — запусти ещё раз так и пришли файл:

```powershell
New-Item -ItemType Directory -Force logs | Out-Null
python tools\build.py --name TGCombatPort --version 0.1.0 --skip-package 2>&1 | Tee-Object -FilePath logs\build_log.txt
```

## Шаг 5. Запустить Creation Kit и загрузить игру

### 5.1. Запуск

Steam → Библиотека → в выпадающем фильтре выбери **Инструменты** → **Skyrim Special Edition Creation Kit** →
**Запустить**. Может появиться предупреждение о бета-версии или лицензии — нажми **OK**.

### 5.2. Окно выбора файлов (Data)

Первым делом CK показывает окно **Data** — список файлов игры. У каждого слева есть квадратик (галочка).

1. Найди в списке `Skyrim.esm` (обычно самый первый) и щёлкни по квадратику слева от названия — появится галочка.
2. Так же отметь `Update.esm`, `Dawnguard.esm`, `HearthFires.esm`, `Dragonborn.esm`.
3. **Больше ничего не отмечай.** Файлы `.bsa` не трогай.
4. **Не нажимай «Set as Active File»** — про это ниже, в «Галочка и активный файл».
5. Нажми **OK**.

Если окна Data нет — открой его вручную: меню **File → Data**.

### Галочка и активный файл — это две разные вещи

Многие на этом путаются, поэтому отдельным абзацем.

- **Галочка** в окне Data значит «CK загрузит этот файл, чтобы я видел его записи». Это не «перезаписать».
  Без галочки на `Skyrim.esm` CK не увидит ни одной вещи из игры и работать будет не с чем.
- **Активный файл** — это один-единственный файл, в который CK будет записывать всё новое. У нас его ещё нет:
  наш плагин `TGCombatPort.esp` создастся при первом сохранении (пункт 5.5). Поэтому кнопку
  **«Set as Active File»** не нажимаем вообще: если сделать активным `Skyrim.esm`, CK попытается писать новые
  записи прямо в файл игры. Галочка на `Skyrim.esm` при этом остаётся — это нормально и обязательно.

**Про свои моды.** Если у тебя уже стоят другие моды (`.esp`/`.esm` в списке Data) — для первого теста их
**не отмечай**. Причина: всё отмеченное автоматически становится **зависимостью** нашего плагина. То есть
`TGCombatPort.esp` начнёт требовать эти моды у каждого, кто его поставит, а если в них что-то не так — ошибка
будет выглядеть как ошибка нашего мода. Отметим их позже, отдельным шагом, когда базовая проверка пройдёт.

**Про скрипты.** Наши четыре скрипта (`TGCP_*.pex`) в этом списке **не появляются и отмечать их не нужно**:
там перечислены только файлы-плагины (`.esm`/`.esp`/`.bsa`). Скрипты — не плагины, игра сама берёт их из
`Data\Scripts`, куда мы их скопировали на шаге 4. Поэтому «моих скриптов нет в окне Data» — так и должно быть.

### 5.3. Ожидание загрузки

CK загружает игру несколько минут. Окно может побелеть и подписать «Не отвечает» — это нормально, **жди**.

Во время загрузки CK почти наверняка покажет несколько окон **Warning**. Два самых частых:

- `MASTERFILE: Potentially duplicate Land (000028df) encountered in file Dawnguard.esm` (второй такой же —
  про `000028fd`) — совпадение ID участков земли между `Dawnguard.esm` и `Skyrim.esm`. Проявляется у всех при
  загрузке официальных DLC, в том числе без активного плагина; к нашему моду и к сохранению файлов игры
  отношения не имеет. Жми **Да**. Источники: обсуждения с точно этими же двумя строками на
  [Nexus](https://forums.nexusmods.com/index.php?/topic/8486228-sse-creation-kit-warning-messages/) и
  [AFK Mods](https://www.afkmods.com/index.php?/topic/5092-creation-kit-sse-fallout-4/).
- Дальше почти всегда идут строки `Non-parent ... exists in both file 'HearthFires.esm' and 'Dawnguard.esm'`
  и `Editor ID ... is not unique` — тоже про несовпадения внутри официальных DLC. Жми **Да**.
- Предупреждения про отсутствующие голосовые файлы (`voice`) или navmesh — тоже обычная картина, жми **Да**.

Смысл кнопок: **Да** — «понял, продолжай загрузку», **Нет** — «не загружать этот файл», **Отмена** — «прекратить
всё». Нам нужны **Да**. Если одинаковых окон много, можно включить «Yes to all».

### 5.4. Что видно после загрузки

Откроется большой серый 3D-вид (Render Window) и несколько окон:

- **Cell View** — список локаций;
- **Object Window** — список всех объектов игры (слева дерево категорий, справа список записей).

Если Object Window не видно — меню **View → Object Window**.

### 5.5. Сразу сохранить новый плагин

1. **File → Save** (или `Ctrl+S`).
2. В окне сохранения введи имя `TGCombatPort` (CK сам добавит `.esp`).
3. Папка — `Data` игры (предлагается по умолчанию).
4. Если спросит, создать ли новый файл — **Yes**.
5. Проверь заголовок окна CK: там должно появиться `TGCombatPort.esp`.

Проверка: в `...\Skyrim Special Edition\Data\` появился `TGCombatPort.esp`. Если да — можно переходить к записям.

## Шаг 6. Создать глобальную переменную

1. В окне **Object Window** слева находится дерево категорий (Actor, Character, Magic, Miscellaneous...).
2. Прокрути до **Miscellaneous**, щёлкни по «+» или стрелке, выбери **Global**.
3. В правой части окна появится список глобальных переменных. Щёлкни **правой кнопкой по пустому месту списка →
   New**.
4. Заполни:
   - **ID**: `TGCP_PlayerBlocking`
   - **Type**: выпадающий список → `Short`
   - **Value**: `0`
5. **OK**.

Проверка: `TGCP_PlayerBlocking` виден в списке Global.

## Шаг 7. Создать квест

1. В дереве Object Window: **Character → Quest**.
2. Правый клик по списку справа → **New**.
3. **ID**: `TGCP_MainQuest`.
4. Поставь галочку **Start Game Enabled** (квест запустится сам при загрузке игры).
5. **OK**.
6. Найди `TGCP_MainQuest` в списке и открой **двойным щелчком**. Появятся вкладки: Quest Stages, Quest Aliases,
   Quest Objectives, Scripts.

## Шаг 8. Алиас на игрока и скрипты

### 8.1. Алиас

1. В открытом квесте перейди на вкладку **Quest Aliases** (третья слева, рядом с Quest Stages).
2. Правый клик по пустой таблице → пункт **New Reference Alias**. (Обрати внимание: пункта «New» нет,
   первый пункт меню называется именно «New Reference Alias». Пункт «New Location Alias» нам не нужен.)
3. Откроется высокое окно **Reference Alias**. Сверху поле **Alias Name** — впиши `PlayerAlias`.
4. Ниже найди **Fill Type** — это группа переключателей/выпадающий список. Выбери **Specific Reference**.
5. Под этим выбором появится ячейка для самого объекта. В левом окошке выбора ячейки (Cell) укажи
   `(any)`, в правом (Ref) — `PlayerRef`: начни вводить `PlayerRef` в поле-фильтре, выдели появившуюся строку.
6. Нажми **OK** в этом окне. Алиас появится в таблице.

Если кнопки **OK** не видно — окно выше экрана, это известная особенность CK. Щёлкни в поле **Alias Name**
и нажми **Shift+Tab** два раза, затем **Enter** — окно сохранится и закроется.

### 8.2. Скрипты на алиасе

Скрипты вешаются не на вкладку **Scripts** квеста (она вверху, правее Misc), а внутрь окна самого алиаса,
в блок **Scripts** справа. Поэтому сначала закрой окно алиаса (пункт 6 выше), а потом открой его заново.

1. Двойной щелчок по строке `PlayerAlias` в таблице — окно алиаса откроется снова.
2. В нём найди блок **Scripts** (справа, ниже настроек Fill Type) и нажми в нём **Add**.
3. Откроется список скриптов из `Data\Scripts`. Выбери `TGCP_PlayerBlockWatcher` → **OK**.
4. Выдели добавленный скрипт в списке → нажми **Properties**.
5. Найди свойство `PlayerBlocking`, щёлкни по ячейке значения → выбери `TGCP_PlayerBlocking` → **OK**.
6. Снова **Add** → `TGCP_AnimEventProbe` (у него нет свойств) → **OK**.
7. **OK** в окне алиаса (если кнопки не видно — снова `Shift+Tab` дважды и `Enter`).

### 8.3. Сохранить

**OK** в окне квеста, затем `Ctrl+S`.

Проверка: оба скрипта видны в списке Scripts без красных пометок. Если в списке **Add** нет наших скриптов,
значит `.pex` не лежат в `Data\Scripts` (шаг 4) или CK был запущен до их копирования — закрой CK, проверь файлы,
открой заново.

skyrim-combat-port\src\plugin\

Это нужно, чтобы записи сохранились в Git, а не только на твоём диске.

## Шаг 10. Включить плагин в игре

Игра запускает только те плагины, которые отмечены в списке. Сделаем это командой (игра должна быть закрыта):

```powershell
python tools\enable_plugin.py --enable TGCombatPort.esp
python tools\enable_plugin.py --status TGCombatPort.esp
```

Ожидаемо: `Включён: TGCombatPort.esp`, затем `TGCombatPort.esp: включён`. Скрипт сам сделает резервную копию
`plugins.txt`.

> Позже, когда перейдём на MO2, включать плагин будешь в менеджере модов, а не этой командой.

**Почему нельзя включить плагин внутри игры.** В Skyrim Special Edition нет списка локальных плагинов
ни в лаунчере (пункт **Data Files** был только в старой Skyrim 2011 года), ни в главном меню: пункт
**Creations** — это магазин Bethesda.net, локальные `.esp` он не показывает
([Reddit](https://www.reddit.com/r/skyrim/comments/1ai2ht4/mod_menu_gone/),
[Nexus](https://forums.nexusmods.com/topic/4989205-data-files-option-missing-from-launcher/)).
Консоль в игре тоже не умеет включать плагины. Список включённых плагинов — это текстовый файл
`%LOCALAPPDATA%\Skyrim Special Edition\plugins.txt`; его правят либо вручную, либо скриптом
(`enable_plugin.py`), либо менеджером модов. Файл `.esp`, положенный в `Data`, сам по себе не включается,
а копия в `src\plugin\` — просто резервная копия в Git, на запуск игры она не влияет.

## Шаг 11. Включить логи Papyrus

Логи нужны, чтобы увидеть работу скриптов. Открой блокнотом:

```
C:\Users\ТВОЁ_ИМЯ\Documents\My Games\Skyrim Special Edition\Skyrim.ini
```

Добавь в конец файла:

```ini
[Papyrus]
bEnableLogging=1
bEnableTrace=1
bLoadDebugInformation=1
```

Сохрани. Если такая секция уже есть — просто поставь `=1`.

## Шаг 12. Первый запуск и первый лог

1. Запусти Skyrim SE (обычный, не SKSE).
2. Начни новую игру или загрузи сохранение.
3. Подожди 10–15 секунд в мире.
4. Выйди из игры.
5. В PowerShell в папке проекта:

```powershell
python tools\collect_logs.py
```

Ожидаемо: отчёт `logs\papyrus_report.txt`, в нём строки

```
[TGCP] block watcher registered on ...
[TGCP] probe: registered 12 candidate events on ...
```

Если этих строк нет — проверь по порядку:

1. Плагин действительно включён: `python tools\enable_plugin.py --status TGCombatPort.esp`.
2. `.pex` лежат в `Data\Scripts` (шаг 4).
3. Логи включены в `Skyrim.ini` (шаг 11), игра была перезапущена после правки.
4. Квест помечен **Start Game Enabled** (шаг 8.1).
5. В `Data` нет второго `TGCombatPort.esp` из старой попытки.

Пришли `logs\papyrus_report.txt` — этого достаточно, чтобы я понял, где застряло.

## Шаг 13. Что делаем после первого лога

1. Зайди в игру, найди любого бандита или волка, подержи блок и получи удар.
2. Снова `python tools\collect_logs.py`.
3. Пришли новый `logs\papyrus_report.txt`.

По строкам `[TGCP] anim event:` станет видно, какие события блока и атак реально приходят. От этого зависит,
можно ли сделать бандита и волков на Papyrus или нужен SKSE.

## Частые проблемы

| Что видишь | Вероятная причина | Что делать |
|---|---|---|
| `python` не распознан | Python не в PATH | переустановить с «Add to PATH» |
| `Не найден компилятор Papyrus` | CK не установлен или стоит в нестандартном месте | `python tools\check_env.py`, прислать вывод |
| В CK нет наших скриптов в Add | `.pex` не в `Data\Scripts` | шаг 4, перезапустить CK |
| При запуске CK нет окна Data | оно было закрыто/скрыто | меню **File → Data** |
| В списке Data нет `HearthFires.esm` | CK другой версии или файл переименован | пришли список файлов, разберёмся |
| Предупреждение `MASTERFILE: Potentially duplicate Land (000028df) … Dawnguard.esm` | обычное поведение CK с официальными DLC, к моду не относится | нажать **Да** (Yes); таких окон может быть несколько — на каждом **Да** |
| CK пишет «Не отвечает» | идёт загрузка мастер-файлов | ждать, не закрывать |
| Не видно окна Object Window | окно закрыто | меню **View → Object Window** |
| Нет пункта **New** в таблице алиасов | он называется **New Reference Alias** | правый клик → **New Reference Alias** |
| В окне алиаса не видно кнопки **OK** | окно выше экрана | щёлкнуть в поле Alias Name, **Shift+Tab** дважды, **Enter** |
| В окне алиаса нет блока Scripts | скрипты алиаса живут в самом окне алиаса, не на вкладке Scripts квеста | прокрутить окно вниз/вправо, искать «Scripts» с кнопкой **Add** |
| CK просит выбрать активный файл | плагин ещё не создан | нажать **OK** и продолжить без активного файла; имя `TGCombatPort` ввести при сохранении (5.5) |
| В окне Data видно мои `.esp`/`.esm` | это другие установленные моды | для первого теста не отмечать, см. «Галочка и активный файл» в 5.2 |
| В окне Data нет моих скриптов | скрипты не плагины | так и должно быть: они грузятся из `Data\Scripts` |
| Игра не видит плагин | не включён в plugins.txt | шаг 10, `--status` |
| В логе нет `[TGCP]` | логи выключены / квест не стартовал | шаги 11 и 8.1 |
| CK падает при сохранении | плагин в нестандартном пути или нет прав | сохранить в `Data`, запустить CK от имени администратора |

## Чего не делать

- Не копировать папку проекта в `Data` игры.
- Не делать `Skyrim.esm` активным файлом в CK.
- Не присылать архив мода, игру или `Data`: нужны только текстовые отчёты.
- Не править `plugins.txt` вручную, если можно использовать `tools\enable_plugin.py`.
